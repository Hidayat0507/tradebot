# UI / UX audit — 2026-10-31

**Scope:** Every page on `feat/pine-phase5` except `/assets` and `/admin`. Each finding is ranked by **impact × how often a user hits it**. No design changes were made.
**Setup:** `next dev` locally with dummy env and a fake Supabase (auth + PostgREST fixtures on :54321). Headless Chrome screenshots at 1440×900 and 390×844 (mobile).
Screenshots and the harness are in `/workspace/ai-logs/tradebot-ux/` on the box, not in the repo:
`01-home` … `16-mobile-bots`, plus `tools/mock-supabase.mjs` and `tools/shoot.mjs`.
**Not covered:** `/assets` was skipped on purpose because it calls private exchange balance APIs. `/admin` was not visited.
**Fixture caveat:** findings marked *(verify)* may be partly caused by the mock data.

## P0 — broken or misleading in ways that can cost money or block the main task

1. **Webhook secret shows the hash, not a usable secret** (`06-bot-detail`). Secrets are now stored hashed at rest (`sha256:…`), and the "Current Secret" box and Copy button show that hash. A user who pastes it into TradingView gets 401 on every alert. Fix direction: show the plaintext once, when it is created or regenerated, and after that show "hidden — regenerate to view".
2. **Create-bot "API Documentation" contradicts the real webhook contract** (`05-bots-create`).
   - The example uses `symbol: "BTCUSDT"`, uppercase `BUY`, `position_size` and `timestamp`.
   - It leaves out the required `bot_id`, `secret`, `ts` and `alert_id`.
   - It hard-codes the endpoint `https://signals.signum.money/trading`.
   - It mentions an "IP allow list" that does not exist.
   - The bot detail page shows the correct format. Users following the create page will fail.
3. **Unit confusion on position size.** Create says "Max Position Size … in base currency (e.g., BTC)" with a default of 0.01. The bots list renders the same field as **`$50`**, and the webhook treats `order_size` as a **% of balance**. Three meanings for one number, on the money path.
4. **Paper vs live is invisible outside `/strategy`.**
   - The bots list and bot detail do not show `mode` (live or paper).
   - Dashboard "Recent Trades", "Active Positions" and "Trading Performance" mix paper (`paper-*`) and live trades with no badge.
   - Headline PnL and win rate (`$32.00`, `100%`) include paper fills.
   - A user cannot tell whether real money moved.

## P1 — usability problems on core flows

5. **`/strategy` form controls are unreadable in the dark theme** (`07`, `08`, `09`, `15`). The textarea, selects and number input render with a light background and very light text, so the Pine code and the selected values are almost invisible. They should use the shared `Input`/`Select`/`Textarea` components.
6. **`/strategy` is not in the main nav.** The only nav items are Dashboard, Bots and Assets. The new flow can only be found by URL, and the dashboard's empty state points to "/strategy" as plain text.
7. **Outdated "Supported" hint on `/strategy`.** It lists only sma/ema/rsi/cross and entry/close. It leaves out atr, macd, `[]` history and `strategy.exit`, and says nothing about the AI fallback flag.
8. **Error states are raw.**
   - A Pine error shows as a monospace `line 2: unsupported identifier ta.vwap` with no guidance and no line highlight in the editor (`09`).
   - Market Overview 500s (Bitget public API 429 under parallel requests) fail silently.
   - "Active Positions" stays on "Loading…" forever.
9. **Dashboard is one very long scroll with no hierarchy** (`03`, `14`). There are 7 stacked cards. The KPIs at the top are small, and important status (paper strategy health, failed orders) is far down. There are no tabs or anchors.
10. **Mobile (390px):**
    - The dashboard tables overflow and squash: the Pine panel columns wrap mid-word, and the Recent Trades columns are cut off (`14`).
    - The nav brand "Trading Bot" wraps onto two lines (`15`).
    - On `/strategy` the trades table wraps dates over 3 lines.
    - There is no horizontal scroll or card layout for tables.
11. **Bot names show as "Unknown Bot"** in Recent Trades and Activity Logs *(verify)*. The code expects `log.bots` to be an array, but PostgREST returns an object for a many-to-one join. This is likely a real bug in the logs parsing (`dashboard/page.tsx:63`, `logs/page.tsx:54`).
12. **Destructive actions sit next to primary ones.** In the bots list, a red "Delete" is next to Pause and Activate on every row. Confirm-dialog quality was not checked.

## P2 — polish, trust and consistency

13. **Landing page claims can't be backed up** (`01`): "2,500+ active bots", "$10M+ volume", "99.9% uptime", testimonials, and "Bank-level security". These are a trust and legal risk. Remove them or source them.
14. **Plan usage reads "You are using NaN of 5 bots"** *(verify; the mock's count header may be the cause)*. Either way, the UI should guard against `NaN`.
15. **Inconsistent naming:**
    - The brand is "Trading Bot" in the app, "Tradebot" in the repo, and the endpoint is "signum".
    - The status badge says "Active"/"Paused" on the list and "Enabled" on the detail page.
    - Pine sample buttons use code names (`emaCross`, `macdAtrStops`).
16. **Timestamps:** locale strings with no timezone in tables, and ISO `2026-01-05T17:00` on `/strategy`. Pick one format and show the TZ.
17. **The Next.js dev indicator overlaps content** on the left in dev builds. This is dev only and can be ignored.
18. **Accessibility:**
    - Several icon-only buttons (copy, refresh) have no labels.
    - Light-on-light text on `/strategy` fails contrast.
    - Small (11–12px) grey text sits on the dark cards in the Pine panel.

## Suggested order for the design phase
1. Fix P0 #1–#4 first: secret display, docs/contract, units, and a paper/live badge everywhere.
2. `/strategy`: themed inputs, nav entry, updated hint, better errors (#5–#8).
3. Restructure the dashboard: KPI row → paper/live split → tabs; mobile tables (#9, #10).
4. Trust and polish (#13–#18).
